One App, Four Ways to Breathe

Jingxin — a minimal meditation guide app, breathing, mindfulness, guidance, and relaxation in four modes.

Proof of a Cross-Platform Mobile Build

Built with Flutter — one codebase that runs on Web / Android / iOS / Windows. A minimal interface that stays focused on meditation itself, undisturbed by feature clutter.

  • Data model: a MeditationSession records duration / mode / completion state.
  • State management: Provider manages the chosen duration and mode, with crisp UI responses.
  • Breathing animation: a custom BreathingCircle component guides the breathing rhythm.
  • Four modes: breathing / mindfulness / guidance / relaxation.

Mail, CRM, and Newsletter in One Chain

FengOffice — AI-unified mail and CRM, folding the infrastructure of content operations into one automated pipeline.

Where Engineering Delivery Meets Marketing Operations

One CLI manages mail, one Docker stack runs Twenty CRM — mail discovery → reply → CRM record, the whole chain wired up. Newsletters are distributed automatically by the Listmonk system.

  • fengmail.py: a CLI mail client, IMAP receive + SMTP reply.
  • Twenty CRM: one-command docker-compose deploy, port 3002.
  • Newsletter: a Listmonk + Postgres subscription system, with AI scripts to add, unsubscribe, and send campaigns.
  • Four-tier mail classification: docs/email-classification.md defines the classification system.

Eighteen Engines, the Best One Wins

Super-Invincible-Search-King — a Playwright-powered all-in-one search tool: images, text, web reading, deep crawling, and anti-bot site scraping.

Treating "Being Blocked" as the Norm

One machine, eighteen engines. CAPTCHAs are skipped automatically, the engine chain falls back by itself, and a real-human browse mode is the final backstop.

  • Five behaviors: image / text / read web / deep crawl / platform fetch (Xueqiu, Bilibili).
  • Twelve image engines + six text engines, covering mainstream and regional search.
  • Six backends: from headless browser to real browser, layered fallbacks.
  • Traceable copyright: each result carries its source and license record.

How I Usually Approach Software Projects

  • Define the real problem first: What are we solving, who will use it, and what does "done" really mean?
  • Choose the right stack: Prioritize deployment and maintenance over tech for tech's sake.
  • Build in layers: Get the structure and flow right first, then refine visuals and experience.
  • Deliver with launch in mind: Documentation, naming, navigation, meta information — all part of shipping.

Advancing with PDCA: plan first, then execute in stages, check, and adjust — never jump into writing messy code. Decouple only after the structure is clear. Don't cram everything together.
