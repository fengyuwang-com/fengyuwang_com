05Three interfaces, one diagnosis

The Two-Layer Interface Principle (2LIP): a software system built for the AI era keeps only two interaction layers. Documents form a third interface that faces the AI and runs vertically across both.

Buttons don't answer. Conversation does.

The conversation layer does

Operating rights go to the conversation layer: create, read, update, delete, workflow triggers and exception handling all happen in natural language, with Skills freezing repeated actions into scripts. Bury an operation inside a button and the AI cannot reach it.

The viewing layer shows

The graphical interface does not disappear, it retreats to a viewing deck: read-only, no writes, for people who do not operate to confirm state at a glance, and for external demonstration. Glanceability has real value — monitoring walls and investor demos still favor fixed views.

The document layer governs

The document is the control plane: the AI reads AGENTS for rules, MISSION for goals and todo for tasks, then writes results back into the ledger and logs. The readership expanded from humans to humans and AI — and the AI is the stricter reader, executing word for word.

PDCA loop plus structure first

Advance with PDCA: plan first, then execute in stages, check and adjust, rather than writing code straight away. Decouple only after the structure is clear, and reuse everything reusable. Observation — the viewing layer — is itself part of Check.

LLM Text Processor

LocalTypeScript

Chunks very long text by strategy and feeds it to large language models in parallel batches, with GUI and CLI sharing one Dockerised service.

It supports several chunking strategies - by character count, by line count, or custom wildcard, regex and heading rules - and three execution modes: serial, parallel with configurable concurrency, and serial with context memory. Around that sit server-side prompt presets, per-chunk live progress, failure retries, pause and stop at any time, and exports either as finished output or as a side-by-side view against the source. Originally a Python and tkinter desktop app, it was rewritten wholesale as a Dockerised TypeScript web service, and its UI structure was later cited as a reference by the FlyGo interface design constitution, and it is the most general-purpose tool in the portfolio and the shared base for long-text processing in both content and investment research.

Python Deterministic Check

LocalPython

Runs nine categories of mathematical operations to verify that the numbers come out bit-identical across interpreters, operating systems and CPU architectures.

It covers nine classes of fundamental operations - big integers, IEEE 754 floating point, 50-digit high-precision decimals, complex numbers including Euler's formula, fast matrix exponentiation and fast-doubling Fibonacci - to determine whether the current Python environment (CPython, PyPy or another interpreter, on different operating systems and CPU architectures) produces exactly identical results for all basic mathematics. The trigger scenarios are concrete: suspecting that an AI or a remote environment is not really running on Python underneath, or seeing the same script produce different numbers on another machine. It is the portfolio's weights-and-measures calibrator, providing a backstop for the reproducibility of investment research computation.
