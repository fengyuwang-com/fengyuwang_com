# 三页合一：tech.html + system.html + system-graph.html

**日期**：2026-10-01
**结果**：`{zh-cn,zh-hk,en}/tech.html` 一页承载三页内容；`system.html` 与 `system-graph.html` 已删除，**不留重定向**（站长明确决定）。

## 起点

`system.html` 与 `system-graph.html` 本来就是同一页被拆开：h1 完全相同，剥离注释后样式表 148 vs 156 条选择器、**值零差异**（graph 多出的 9 条全是 `.sn2-*` 画布样式）。再加 `tech.html`，读者要在导航里点三次才能走完一条线。

## 主 URL 为什么是 tech.html

`tech.html` 身上挂着 **51 处入链 / 33 个页面**，外加 5 条重定向（`/tech` 302、3 条历史 `/portfolio.html` 301）。选它意味着 51 处链接一行不用改写。代价是另外 51 处要删（导航模板 4 行 + 3 个 `system-projects.html` 的 cta-row），已全部处理并复核为零残留引用。

## 页面结构（15 个内容块）

```
快照 hero（沿用 system 的：eyebrow + h1 + tagline + fx-ekg + 三项统计）
  → #domains   六大领域 SVG（h2 改为「技术不是孤岛」，tech 的那句折进副标题）
  → #method    方法三句话
  → #net       项目关系图画布（78 节点 / 135 边）
  → card-grid  3 个旗舰项目
  → tech 原有的 12 个区块
  → 合并后的 link-card
```

**只留一个 h1。** 建第二个 `.marketing-hero` 会在页面中段开一道 92px 空带，就是最初那个「白斑」。tech 的「技术」降级为 `#domains` 的 h2 标签，它那句「结构设计先于代码，交付才是目的」折进副标题。

**1200px 按块放开，不按页放开。** 画布需要宽度，但全局 `1200px` 会把 15 个块的文字栏一起撑开。收窄成 `#net .block-inner{ max-width:1200px; }`，其余保持 720px；`#domains` 不放开（SVG `viewBox` 自适应）。DESIGN §6.1 已补上这一形式。

**`.content-block { scroll-margin-top: 76px }` 是功能性必需。** `tech.html` 有 8 处 `scrollIntoView`（9 张 mkt-card 的点击）却**没有**这条规则 —— 合并前靠卡片够高侥幸没被固定导航栏盖住。合并后区块相邻，丢了这条 9 张卡全部点进导航栏底下。实测：8 个目标全部落在 76px，导航栏 44px，余量 32px。

**reveal / rail / progress 各只留一份。** `fx-rail` 建成静态 3 项（`#domains` / `#method` / `#net`），与 `system-projects.html` 的先例一致；graph 原有的 rail 是**空 `<nav>`**，无冲突。`fx-rv` 不加给 tech 原有区块 —— 那是没人要求的视觉改动。

## 导航改动

`技术概览`（`portfolioOverview`）已经指向 tech.html，合并后它**同时就是**体系全景和关系图。Tech ▾ 下拉里再留两条同 href 不同标签的 `<li>`，正是「合并失败」的外观信号。删除：桌面 submenu 2 条 + 移动 drawer 2 条模板行，`systemHref`/`systemGraphHref`/`system`/`systemGraph` 各 3 语言共 12 个键。`systemProjectsHref` 保留（那个页面还在）。

`system-projects.html` 的 link-card 原有两行 cta-row：第一行两个链接都指向被删页面，整个行删掉；caption 从「一张图看 78 个项目怎么连成网」改为「78 个项目，往下看」——图已经不在这一页了。剩下的行去掉了 `margin-top:14px`（它不再是第二行）。

## 已知后果

`/{lang}/system` 与 `/{lang}/system-graph` **404，无重定向**。这是站长的明确选择（已告知后果后确认）。落地前值得看一眼 Cloudflare Pages 日志，确认这两个地址没有外部书签或外链流量。

## 复现方式

合并脚本是一次性的，留在 `.merge_tech_system.py`。重跑前需从 `.merge_backup/{lang}/` 恢复三份原始 tech.html（脚本自带幂等守卫，但**不**恢复被删的两个文件）。

两个必须记住的坑（详见 `docs/guide/pitfalls.md` §17）：

1. `<style>`/`<script>` 是**纯文本**不是标记，深度遍历必须在这两种标签处直接停 —— 否则一次吞掉约 9KB 正文。
2. `tech.html` 的 `<head>` **本来就有 3 个 `<style>` 开、2 个 `</style>` 闭**（img-caption 那张表开在 prefers-reduced-motion 表里面，共用一个闭合标签，`git show HEAD:zh-cn/tech.html` 可复核，早于本次改动）。按嵌套切会留下没闭合的表，**它会把后面所有内容当纯文本吞掉**，包括刚注入的合并样式表 —— 症状是画布缩回 720px、左右白斑回来，而 `check_site.py` 全绿。
