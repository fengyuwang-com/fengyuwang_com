# 通用文档整理法（所有项目复用）

> 本篇与具体项目无关，任何仓库照抄执行。本站是首个验证实例：`AGENTS.md` 639→66 行，`docs/` 重组为"根下只留文件夹"，见 §7 对照表。

目标一句话：**开工只读一页（入口 <150 行），细节按需再查；加新规则只改一处。**

---

## 1. 诊断（先量再动）

1. 数行数：入口文件多少行，设计文档多少行，记下改前基线。
2. 找重复：同一概念在两个文件都展开讲 = 重复，必须只留一处全文，其余只留一句话加链接。
3. 列裸文档：`docs/` 根下所有裸 `.md`，每个判定去向（手册 / 决策 / 归档 / 删除）。

## 2. 划分线：不可逆测试（唯一标准）

新条目进不进入口正文，只看一条：**违反之后能不能低成本改回来**。

- 改不回来（分支、安全、架构、不变量）→ 留入口正文，一句话红线。
- 改得回来（写法、样式参数、踩坑细节）→ 搬进手册，入口只留链接。

找"根本性条目"的方法：问"新来的 AI 不看这条，会不会闯不可逆的祸"。会 → 根本性，留正文；不会 → 藏链接后。

## 3. 目标结构

```
AGENTS.md（入口，<150 行，只 5 块）
  1. 项目一句话 + 架构铁律
  2. 目录与命令（含 Todo 纪律）
  3. 分支与门禁（一句话 + 链接）
  4. 安全红线（原文逐字保留，禁改写）
  5. 任务索引表（任务 → 读哪份）
docs/README.md（地图：每个文件夹放什么 + 例外说明）
docs/guide/（常查手册，一篇一事，按主题分文件）
docs/decisions/（架构决策，永久有效）
docs/archive/（一次性历史，只读，日常不读）
docs/ 根：只放 README + 文件夹，不放裸文档（未完成的活文档可暂留，必须在 README 注明）
指针文件（如 CLAUDE.md）：只指入口，不复制内容
冻结存档（如会话记录 FENGMEM）：一字不动；旧路径变化只在地图里注明，不动原文
```

## 4. 执行顺序（防丢历史）

1. **先落盘计划，再找独立 reviewer 评审**，意见并入计划。事关重大的重组不允许边想边改。
2. **纯搬运单独提交**：`git mv` 或原文搬运不改写，保证 `git log --follow` 可追溯。
3. **瘦身改写单独提交**：删重复节，断链处同 commit 修掉，不留"下次再修"。
4. **新问题固化成检查**：重组中暴露的、能机械判定的问题，加进检查脚本，不许"只修不加检查"。
5. **验证**：改后行数对比 + 死链检查 + 快速检查全绿 → commit（日常分支）；全量检查只在发版到主线前跑。

## 5. 防复胖锁（必加）

入口文件加一句话锁：**新增规则默认进手册，不进正文；进正文只认"不可逆"标准**。以后加新坑，只改手册里的一篇 + 检查脚本，不两边同步。

## 6. Todo 纪律

先记 todo 再开工；做完即勾掉清掉，不留已完成堆积；聊到但暂未做的先记入 `todo.md`，不口头欠账。

## 7. 本站实例对照（抄方法时参考）

| 通用角色 | 本站实例 |
