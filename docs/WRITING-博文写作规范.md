# WRITING — 博文写作规范(v1)

> 总纲(用户原话):「网站设计是让人最短的时间看出我最多的想法,而文章的设计是人家用很多的时间看出我很多的想法。」
> 本文是全部博文的唯一标准。文章未动笔,规矩先立住。

## 〇、三条铁律(用户原话,一切条款由此推出)

1. **每一篇文章都来自我的言论。** 没有出处,不写。
2. **用语简洁且文雅。** 简洁是删出来的,文雅是净出来的。
3. **掷地有声,错落有致。** 每段有一个落点,全文有一种呼吸。

---

## 一、材料律——写什么

1. **一篇一意。** 一篇文章只装一个想法。装两个,拆成两篇。
2. **逐字有据。** 核心论断必须能在 `docs/notes/{A,B,C,D,E}.md` 里找到篇号和逐字引文。引文写进正文时保持逐字;引文找不到,就不是这篇文章。
3. **标注谱系。** 每篇文章开头定性一句话,三选一:自创 / 引用他人 / 常识重述。读者有权知道思想的产权。
4. **金句锚点。** 每篇至少埋一处他的原话(「」内,附篇号)。原话是骨,转述是肉。
5. **脏字净化。** 原话里的粗口以「……」截去或轻度改写,不改语气,不改判断。例:「规则本身就是傻逼定的」(024)→ 引用时作「规则本身就是……定的」或转述为「规则是由不值得信任的人定的」。
6. **文末出处。** 尾行固定格式:`出处:元宝对话 篇024〈标题〉`,篇号即 `conversations_top/NNN_*.md` 的编号。这是全站统一的信用背书。

## 二、语言律——怎么写

### 简洁四则
1. **一句一意。** 一句话只说一件事。两件事,断开。
2. **删副词。** 「非常」「特别」「真的」「其实」,十个删九个,意思不减。
3. **数字优先。** 能用数字,不用形容。「很贵」不如「280 块的 120Hz 显示器」。
4. **600–1500 字封顶。** 超过 1500 字,说明这一篇装了两个想法。

### 文雅四则
1. **无网络腔。** 「家人们」「yyds」「绝绝子」一律不进正文。他知道分寸:「家人们谁懂?肯定不是贴吧的语气」(011)。
2. **无 AI 腔。** 禁用:值得注意的是 / 总而言之 / 综上所述 / 在当今时代 / 让我们 / 不可否认。这些词出现一处,退回重写。
3. **量词准确。** 名词精确到物:不说「一些设备」,说「五台电脑、十来部手机」(013)。
4. **庄谐有度。** 幽默出自事实的反差(「老子是甲骨文数据库创始人」),不出自挤眉弄眼。全文不使用 emoji。

### 掷地三则
1. **段末落重音。** 每段最后一句是这段最重的一句。结论放段尾,不放段中。
2. **首句即断言。** 文章第一句就是判断,不做铺垫。禁用「随着……的发展」开头。
3. **不对冲。** 保留他的判断语气。「我觉得 macOS 都做到了」就写「macOS 都做到了」;确需保留犹疑,只用一处「我错了」,不用十处「可能」。

### 错落三则
1. **长短相间。** 连续三句等长,即失败。短句断言,长句展开,读来有呼吸。
2. **段落二至四句。** 超过四句,找断点切分。允许全文有一处「一句成段」——放在最重的判断上。
3. **小标题克制。** 千字文至多两个小标题,也可以没有。标题即断言(「苹果正在变成 IBM」),不用「浅析」「浅谈」。

## 三、结构律——骨架

```
标题    ≤ 15 字,断言式,不用冒号堆砌副题
首段    三句内:亮出这一个想法(或亮出锚点金句)
中段    2–4 节:每一节推进一步,节末落重音;证据(数字/引文)在其中一节
收束    回扣标题,一句收,不总结全文、不喊口号
尾行    出处:元宝对话 篇NNN〈对话标题〉
```

字数分配参考:首段 10%,中段 75%,收束 15%。

## 四、三语律——发布门槛

1. **zh-cn 定稿** → opencc-js 转 **zh-hk**(人工复查:王豐羽→王丰羽)→ 译 **en**。
2. 三语齐备才上线;缺一门语言,文章留在草稿区。
3. 术语表统一(全文共用,新增术语先入表):狗拿钱定理=The Dog-Takes-the-Money Theorem;收费站理论=Tollbooth Theory;不可能三角=Impossibility Triangle;恐惧极点=Fear Extremum。
4. 数字用半角,日期用 YYYY-MM-DD,千位不加逗号以外分隔符。

## 五、禁则(黑名单,一票退回)

- ❌ AI 腔套话(见二·文雅 2)
- ❌ 排比凑气势:三连排比以上,删到只剩最重的一联
- ❌ 免责声明:「本文不构成投资建议」不写;谱系标注(一·3)就是诚实的免责
- ❌ 解释显然之事:读者不需要被告知什么是 Docker
- ❌ 注水:为凑 1500 字而重复例证。短于 600 字而完整,好于 1500 字而注水
- ❌ 编造引文:引号内必须是 notes 里的逐字原文
- ❌ 脏字直接上稿(见一·5)

## 六、验收清单(每篇发布前自查)

1. 这一个想法,一句话能说出来吗?(说出这句,就是文章的首句候选)
2. 出处篇号找得到吗?引文逐字吗?
3. 谱系标了吗?(自创/引用/重述)
4. 删掉 10% 的字,意思无损吗?——那就删。
5. 朗读一遍:有没有连读三句等长?有没有读不换气的长句?
6. 每段末句,是不是这一段最重的一句?
7. 黑名单词汇,一个都没有吗?
8. 至少一处他的逐字原话吗?
9. zh-hk 和 en 有了吗?
10. 600–1500 字了吗?

十项全过,发布;一项不过,改完再过。

## 七、示范(改写一段,立此存照)

**原材料**(篇004,逐字):
> 「我有一个狗拿钱定理,当应该有的钱没有了的时候,这钱肯定是被狗拿走的。我知道这是搞笑的,但是这很本质。」「钱不会消失,钱只会转移。」

**按本规范成文的首段**:

钱不会消失,只会换主人。所以当你应得的钱不见了,不必问钱去了哪里——要问狗在哪里。恒大两万亿,人生三万天,一天要欠一个亿,这笔账怎么算都算不丢,因为它根本没有丢。我给这个判断起了个名字,叫狗拿钱定理。听起来像玩笑,用起来是手术刀。

**自评**:四句,长短相间;「手术刀」落重音;「一天要欠一个亿」是数字优先;无脏字,无套话;只装一个想法(定理+公理),出处可回溯。
