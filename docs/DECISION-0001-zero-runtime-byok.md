# 架构决策记录 0001：零运行时 + BYOK（用户自带 API Key）

**状态**：已批准（2026-09-05，王丰羽确认）
**影响范围**：全站架构、一切新功能、未来所有 AI 相关特性

## 决策

本站**永久保持纯静态（0 运行时）**，部署目标只有 Cloudflare Pages。不做任何形式的自建后端、数据库、常驻服务或独立子域部署。

站点上的一切 AI 能力（对话、分析、生成等）采用 **BYOK（Bring Your Own Key）** 模式：访客填入自己的 AI 提供商 API Key，由**浏览器端 JavaScript 直接调用提供商 API**，本站服务器（即 CF Pages 静态托管）不经手任何请求。

## 已否决的替代方案（不要再次提议）

| 方案 | 否决原因 |
|---|---|
| 自建后端服务器 | 运维复杂度高；CF Pages 免费额度足够；不想维护任何服务器 |
| 独立部署各系统（Worker/子域，如 invest.fengyuwang.com） | 复杂度过高，暂时搁置（未来若做，须重新开决策记录） |
| 站内采访机器人 + D1/KV 存会话 | 依赖后端存储，与 0 运行时冲突；采访暂缓，若重启须改为纯前端方案（localStorage + BYOK） |

## BYOK 实施规范（未来任何 AI 功能必须遵守）

1. **Key 只存访客浏览器 localStorage**，永不上传、永不经手任何服务器；页面上必须明示这一点。
2. **前端直连提供商 API**：OpenAI / Google Gemini 支持浏览器 CORS 直接调用；Anthropic 需加 `anthropic-dangerous-direct-browser-access: true` 请求头。所有主流提供商走各自官方端点，本站不设任何代理。
3. **无 Key 优雅降级**：未填 Key 时功能隐藏或显示引导文案，页面其余部分完全正常——AI 是增强，不是依赖。
4. **失败要有兜底**：配额超限、Key 无效、网络错误都需捕获并给出人话提示。
5. **成本归属清晰**：消耗的是访客自己的额度，UI 上不得暗示本站承担费用。

## 什么时候允许重新讨论本决策

- 某功能在纯前端 + BYOK 下确实无法实现，且该功能被证明有真实访客需求；
- Cloudflare Pages 免费额度无法承载静态流量；
- 用户主动要求引入后端。

满足任一条件时，新开一条决策记录（DECISION-0002+），不得悄悄偏离本原则。
