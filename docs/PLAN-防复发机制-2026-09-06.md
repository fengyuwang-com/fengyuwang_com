# 防复发机制方案（暗色模式 / 三语转换 / 硬编码文案 / 全站 debug）

2026-09-06。由三个真实 bug 触发：① en 文章页「返回博客」硬编码中文；② en/zh-hk 首页 What's New 缺 FengInvest 卡片；③ en 版文章内嵌简历模板残留中文。

## 一、核心原则：三类问题，三种拦截点

1. **机械类 bug（漏翻、硬编码、卡片不对等）→ 脚本拦**。写进 `tools/check_site.py`，每次部署前跑，FAIL 挡发布。
2. **渲染类 bug（暗色模式、排版溢出、移动端）→ 双保险**：脚本静态层查「成对出现」（如新增一段 `.foo` 样式时是否同时写了 `body[data-theme="dark"] .foo`），浏览器渲染层用截图实测（清单第十节）。
3. **人的判断类（观点质量、引用是否故意保留中文）→ 白名单 + 人工**。脚本报出来，人裁决后加白名单（如 en 版老子页保留《道德经》原文 + 拼音，是故意的，已加白名单）。

## 二、check_site.py 已新增的检查（v2.1）

1. en 博文正文汉字 >50 → FAIL（slug/translationKey 的中文不算，URL 保持不变）。
2. en 全部静态页可见文本出现连续汉字 → FAIL（白名单：王丰羽 / 静心 / 老子原文引用）。
3. en 博文部署页出现中文 UI 文案（返回博客/上一页/下一页/搜索文章/排序等清单）→ FAIL。
4. 三语首页 FengInvest 卡片数量对等 → 不等 FAIL。
5. 三语根目录一级页面清单对等（缺页/多页）→ FAIL。

## 三、根治硬编码 UI 文案：约定

- Hugo 模板里**任何面向读者的文字都必须套语言条件**，参照 `blog/list.html` 的既有写法：
  `{{ if eq .Site.Language.Lang "en" }}Back to Blog{{ else }}返回博客{{ end }}`
- 文字量增多后升级为 Hugo i18n 文件（`hugo/i18n/en.toml` / `zh-cn.toml`），模板只写 `{{ i18n "backToBlog" }}`——建议文章超过 150 篇时做这一次性重构。
- 新增静态页时三语必须同批交付，脚本第 10/11 条会兜底。

## 四、暗色模式根治：约定

- 给任何区块写浅色样式时，**同一提交内必须写对应的 `body[data-theme="dark"]` 覆盖**；做不到的区块明确声明继承全局背景。
- 静态检查（清单第九节，待实现进脚本）：扫描每个 HTML 内联样式里自定义 class 的浅色声明，核对是否存在同名 dark 覆盖，缺失则 WARN。
- 渲染级验收：改版后用浏览器工具切 `data-theme="dark"` 截图抽查首页 + 博客列表 + 文章页 + 移动端 375px（人工触发，一次性成本约 10 分钟）。

## 五、三语转换根治：约定

- zh-hk 一律由 zh-cn 用 opencc s2hk 机械转换 + 白名单保护（王丰羽），脚本已查简体泄漏；上下文相关字（里/干/佣/游）人工扫。
- en 永远人工翻译，脚本只查「残留量」（汉字 >50 FAIL），不查翻译质量。
- 允许 zh 文夹英文术语；en 页出现汉字默认视为 bug，白名单需注明理由。

## 六、全站 debug 的常态机制

1. **每次内容变更后**：`python3 tools/check_site.py`（<10 秒），FAIL 不推送。
2. **每次结构/模板变更后**：check_site.py + 手动跑一遍 deploy.sh 后抽查 3 个代表页。
3. **每次大改版后**：按 `docs/CHECKLIST-全站检测清单.md` 的第十节做渲染级抽查（暗色 + 移动端 + 截图对比）。
4. **上线后**：CF Pages 部署完成后 WebFetch 线上 URL 抽查新页（清单独立一节）。
5. 脚本测不到的（观点质量、视觉审美、交互手感）永远是人工，清单第十二节已列明。
