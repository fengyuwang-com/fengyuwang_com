# 计划：暗色模式对比度审计 + 审查脚本增强（2026-09-06）

## 用户报告
暗色模式下，本应"亮色字体"的元素变成了暗色字体（例如蓝色底上出现黑色/灰色的字），要求：
1. 全站排查并修复；
2. 把这个检查固化到全站审查脚本；
3. 把之前做的全站搜索也纳入审查脚本。

## 现场确认
- 之前全站搜索改动完好（hugo.toml JSON 输出、blog/list.json、list.html searchResults、各语言 index.json 已部署）。
- 站点 = hugo 生成的 {lang}/blog/** + 根目录静态页（en/ai.html、fengoffice.html 等遗留页）+ 共享导航（assets/js/shared-subpage-navbar.js）。
- 纯静态 grep 无法可靠判断"暗色下颜色是否可读"，必须真渲染。

## 方案
### 1. 新脚本 tools/check_dark.py（浏览器真实渲染审计）
- playwright 无头 Chromium，遍历全站页面（与 check_site.py 同一页面发现逻辑）。
- 每页设 body[data-theme="dark"]，枚举可见含直接文本的元素：
  - 计算实际 color 与"有效背景"（沿祖先链找第一个非透明背景，混合到页面底色）；
  - WCAG 对比度 < 4.5（大字 < 3.0）判定为问题；
  - 按页面输出问题元素（selector、文字样例、前景/背景色、对比度）。
- 退出码：有 P1 问题则非零，方便并入审查流程。

### 2. 修复
- 按审计结果逐个补 `body[data-theme="dark"]` 覆盖（blog 模板内联 CSS、blog-static.css、共享导航、遗留页）。
- blog-static.css 与 assets/css/blog-static.css 是同一文件的两份拷贝，改根目录一份后同步另一份。

### 3. check_site.py 增强
- 【全站搜索检查】每个语言 blog/index.json 存在、条目数 ≥ 90、字段齐全（url/title/content/tags）；blog 列表页 HTML 含 blogSearch/searchResults 且引用 index.json。
- 【暗色检查】若 playwright 可用则内嵌调用 check_dark 的结果并计入总报告；不可用时提示跳过（不阻塞）。

### 4. 验证
- 跑 check_site.py（含新检查）全绿。
- 浏览器实测暗色模式：博客列表/文章/标签页/遗留页抽验，确认无蓝底黑字。
- 重新构建部署到仓库根（CF Pages 源），commit + push dev；master 不动。

## 不做
- 不改 tag 云/term.html 的功能逻辑；不引入运行时依赖变更；不动 master。
