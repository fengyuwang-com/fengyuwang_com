## 素材（仅语料内；本篇素材主体为对话中完整转述的行业事实，站长原话仅一句"给大姐解释一下这个事情"，语气取"讲给外行听"的定位）
- Kaplan 2020：参数增长应比数据快，约 2.7 比 1；行业因此堆万亿参数，把参数量当进步必经之路。
- Chinchilla 2022（Hoffmann，四百多个模型重做实验）：算力最优约每参数 20 Token；算力增加时参数与数据应同速增长。回头看过往最大模型=算力分配最失衡的一批，参数堆太快数据没跟上。
- 第三版账本：模型上线后每天被调用几十亿次，推理成本远大于一次训练；把这笔账算进去，最优解往更小、训练更久的模型移动。
- MoE 时代：总参数=装下多少知识/事实/长尾信息；激活参数+每次前向有效深度=长程推理能力。需记忆的任务吃参数量，需推理的任务吃数据；固定每参数 Token 数继续加总参数可能让推理变差，激活更多专家反而稳定提升推理。
- 案例：GLM-5.3 与 GLM-5.2 基座完全相同（总参数 753B、激活 40B），AA 指数 53→60，Coding 体感国产 SOTA——一次控制变量实验：不改硬件，只改数据与算法。
- 结论：大模型多聪明没法被总参数量概括；Scaling 没停，从越堆越大的数字变成寻找最优解的游戏。

## 立破成
- 立：参数量单独说明不了什么，必须跟数据、算力分配、运行条件放在一起看。
- 破（最强反论）：万亿次大模型的既有事实——行业曾经真的相信堆参数就是进步，且为它付出了算力失衡的学费。
- 成：Scaling 依然在继续，但目标函数变了：从"更大"到"更优"，钱从买参数挪到买数据与算法。
