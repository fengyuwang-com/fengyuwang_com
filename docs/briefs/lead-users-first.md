# Brief — lead-users-first（第 38 轮）

## ① 想法一句话
需求不在实验室里，在领先用户手里：先感知到需求痛点的那批人早就在 DIY 解法，谁先接住他们的"粘性信息"，谁就把本地偏好变成可复制的玩法。

## ② 素材引文（全部出自 conversations/ISOM5370 团队项目评估_205634.md）
- L137（逐字）："正如 von Hippel (2005) 所言，领先用户在需求前沿产生的实践经验与'粘性信息'更适合作为共创与功能迭代的依据——这类用户往往比普通用户更早感知需求痛点，其反馈能帮助平台快速将本地化偏好转化为可复制的玩法（如日本市场的动漫挑战后续延伸至东南亚二次元社群）。"
- L137（逐字）："例如平台会根据不同国家的文化偏好与用户数据调整内容策略，在日本推出动漫绘画挑战。"

## ③ 对手戏回合表（反方无人称）
1. 开篇：一个玩法从一国火到另一国之前，最早把它玩出来的那批人叫什么——领先用户不是玩家头衔，是需求的天气预报。
2. 反方一（有人说）：洞察靠市场调研，问卷撒得够广就能找到需求 → 驳：问卷问的是平均值，平均值里没有尚未成型的需求；领先用户比普通用户更早感知痛点，他们的经验是需求前沿的实况，不是抽样。调研找到的是今天的用户，领先用户是明年的。
3. 反方二（也有人说）：领先用户是小众极端分子，跟着他们走会把产品带偏 → 接一半：小众是真的。再驳：粘性信息难转移，恰好因为它长在真实使用场景里，市面上买不到；做法不是照抄极端需求，而是把本地化偏好转成可复制的玩法——日本动漫挑战延伸到东南亚二次元社群，路径是提炼不是照搬。
4. 反方三（还有人说）：平台有数据，算法比用户更懂需求 → 收：数据看得见行为，看不见动机；领先用户的创作与参与信号是行为和动机一起给的。算法负责放大已经验证的信号，负责"先验证"的是人。
5. 收口：创新的民主化不是把研发下放给群众，是承认需求前沿的情报早就在用户手里——研发的最后一公里，是从领先用户那里把粘性信息接回来。

## ④ 八法选 1-3
对账法（问卷均值 vs 需求前沿实况）、分岔法（照搬极端需求 vs 提炼可复制玩法）。

## ⑤ 五气配比
断 ≥2、怀 ≥2、察 ≥2，悯 1（落在"长在真实使用场景里"一句），谐 0。

## ⑦ 不适用边界
