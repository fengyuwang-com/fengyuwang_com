# brief — hold-the-reservation《订位容易，留位难》

## ① 想法一句话
服务的失败多败在"留"，不在"接"——谁都会接受预订，守住预订才是预订的本体；喜剧把这个机制演得比教科书准。

## ② 素材引文（逐字+出处，≥3）
1. "是的，收到了。但很遗憾，我们的车都租完了。" / "但预订就是要把车保留着呀。这就是为什么要预订。" — Customer Service Automation_240130.md L6-24（Seinfeld 租车柜台桥段，讲师课堂用作"客户服务自动化出错"的例证）
2. "所以你知道怎么接受预订，却不知道怎么保留预订，而保留预订才是预订中最重要的部分。谁都能接受预订。" — 同上 L24（讲师保留此句并点评"这就是所谓的客户服务出错"，见 L40 开头）
3. "很抱歉，我的主管说我们无能为力。" / 后台对白："他们以为我在和你说话，所以你就假装在和我说话……看起来我在说话，但实际上我什么都没说。" — 同上 L6-24（升级投诉的表演：流程在走，事没人办）
4. "我们还有一辆紧凑型车，如果你想要的话。" — 同上 L24（结案方式：不接受过错，只给替代品）

## ③ 对手戏回合表（3-6 承重回合）
- R1 反方「喜剧个例论」：情景喜剧夸张编的，现实服务不至于。→ 正面接：喜剧的规则是放大常识——观众当场笑，是因为谁都遇过"接了没留"：下单秒回、履约失踪；讲师拿它开课，正因为它是机制不是段子。夸张的是台词，不夸张的是结构。
- R2 反方「超售合理论」：租车行机票超售是行业惯例，用概率挤掉空占资源的人，效率优先没有错。→ 接：惯例成立的前提是承担后果——超售的行当配着补偿、改签、升舱的全套动作，那叫管理概率；段子里的柜台既没守住车，也不认账，只推给"主管说无能为力"，这不是效率，是把风险全部转嫁给预订的人。"接了"是企业的事，"留不住"变成了客户的事。
- R3 反方「自动化背锅论」：这是人工柜台，跟自动化无关；换成系统反而有据可查。→ 接：转写课的主题恰恰是"自动化也会走偏"——系统照样能只做"接"那一半：确认邮件秒到，车辆调度没人管；技术放大的是流程，流程里缺"留"，系统就把缺也放大。背锅的从来不是工具，是只考核接单不考核留单的机制。
- R4 反方「补救无用论」：车就是没了，怎么做都是错，怪服务没必要。→ 接：资源真没了不算罪，罪在结案方式——不承认过错，不主动补救，只甩出替代品和一句"无能为力"；同样的车荒，先认账再给选择，客户记住的就是另一家公司。留位难，难的不是车，是认账的那一步。

## ④ 八法选1-3
主：断（预订的本体在保留不在接受）+ 察（后台表演：流程在走，事没人办）。

## ⑤ 五气配比
断 3 / 怀 2 / 察 2 / 悯 1 / 谐 1

## ⑥ 形状
开场直接进柜台对白（"收到了。但很遗憾……"），中段拆后台表演+三回合反方，收口：接单是能力的下限，留单是信用的本体；订出去的是纸，留住的才是预订。

## ⑦ 不适用边界
- Seinfeld 桥段为虚构喜剧例证，正文明确"喜剧桥段"口径，不当真实事件引用。
- 不写超售定价模型、不写客服排班。
- 与 persona-as-contract 划界：那篇写品牌人格化承诺抬高容错标准，本篇写运营的"接与留"。
- 与 complaint-flip-side 不共用"投诉"主线，本篇只在 R4 触到认账，不展开投诉处理。
